# UESTC-MoonCheck

基于 Python 的宿舍晚间打卡管理网站，支持多人使用，通过 Docker Compose 部署。

## 功能

- 用户自行注册，总管理员管理注册开关、用户状态和系统位置预设。
- 每个用户独立保存学校账号、打卡计划和操作记录。
- 检查登录并查询今日记录，不提交打卡；已打卡时隐藏“立即打卡”。
- 支持系统预设、手动坐标和浏览器定位，提交地址由学校接口获取。
- 提前半小时准备登录，支持定时执行、有限重试和时间、位置浮动。
- 提交后重新查询记录，确认成功后当天不再重复提交。
- 按北京时间每日更新今日状态，历史打卡结果保留在记录中。
- 支持记录查询和 CSV 导出。
- 数据持久化、容器健康检查和自动重启，域名部署支持自动 HTTPS。

技术栈：Flask · Waitress · SQLite · Caddy

## 环境要求

- Linux 服务器，已安装 Docker Engine 和 Docker Compose 插件。
- 能访问 Docker 镜像仓库、Python 包源及学校认证和打卡接口。
- 域名部署需要正确解析域名，放行 TCP 80、443，且端口未被其他服务占用。

检查环境：

```bash
sudo docker --version
sudo docker compose version
```

安装参考：[Docker 官方文档](https://docs.docker.com/engine/install/)。

## 快速部署

下载仓库 ZIP 并解压，或通过 Git 克隆。进入包含 `compose.yaml` 的项目目录，执行：

```bash
sudo bash mooncheck.sh start
```

首次启动会构建镜像、生成 `.env`，并显示首次设置令牌。

### 有域名

在提示中输入域名，例如 `checkin.example.com`，不要带协议、端口或路径。

确认域名解析和防火墙配置后，访问 `https://checkin.example.com`。Caddy 自动申请并续期证书。首次签发可能需要等待，可通过日志查看结果。

### 暂无域名

在提示中直接回车。默认仅监听 `127.0.0.1:8080`，不能通过公网 IP 直接访问。

在自己电脑的终端执行 SSH 转发，保持窗口打开：

```bash
ssh -N -L 8080:127.0.0.1:8080 用户名@服务器公网IP
```

浏览器访问 `http://localhost:8080`。

### 公网 IP 临时测试

先按“暂无域名”启动，确保 `.env` 已生成。编辑 `.env` 中的对应项，替换示例 IP，保留原 `SETUP_TOKEN` 和其他配置：

```dotenv
DOMAIN=203.0.113.10
SITE_ADDRESS=http://203.0.113.10
BIND_IP=0.0.0.0
HTTP_PORT=8080
SECURE_COOKIE=0
```

执行 `sudo docker compose up -d` 应用配置，放行 TCP 8080，然后访问 `http://实际公网IP:8080`。此方式使用明文 HTTP，仅用于临时测试；正式使用请配置域名和 HTTPS。

## 使用方法

### 1. 创建网站账号

首次打开网站，使用启动脚本显示的设置令牌创建总管理员。令牌保存在 `.env` 的 `SETUP_TOKEN`，仅用于首次创建管理员，不是日常登录密码。迁移了完整数据的用户直接使用原账号登录。

管理员可以在“系统管理”中开放或关闭注册、启用或停用用户、维护位置预设。其他用户通过注册页面创建自己的账号。每个人的学校账号、计划和打卡记录相互独立；每个用户可以添加多个学校账号，并使用自己的每日打卡计划。

### 2. 设置系统位置预设

管理员进入“系统管理 → 添加预设”，填写名称、纬度、经度、坐标系和精度，保存后用户即可选择。

账号使用预设时，执行任务会读取管理员最新保存的位置。管理员更新预设后，引用该预设的账号会同步使用新位置。预设停用后不会自动换成其他位置。

下方的学知组团坐标表可用于填写参考。请注意表格按“经度、纬度”排列，表单按各字段名称填写。

### 3. 添加学校账号

进入“打卡账号 → 添加账号”，填写：

| 字段 | 填写内容 |
| --- | --- |
| 备注 | 便于自己识别的账号名称 |
| 学号 | 学校统一认证账号 |
| 学校密码 | 学校统一认证密码，与网站登录密码不同 |
| 信任浏览器 | 本人已验证浏览器的 `MULTIFACTOR_BROWSER_FINGERPRINT` Cookie 值 |
| 位置 | 默认选择系统预设，也可切换手动填写实际坐标 |
| 参与自动打卡 | 勾选后，该学校账号才会参与定时任务 |

信任浏览器的获取方式：在学校网站登录并信任浏览器后，按 F12 打开开发者工具，在“应用 / Application → Cookies → idas.uestc.edu.cn”中复制 `MULTIFACTOR_BROWSER_FINGERPRINT` 的值。填写的是该 Cookie 的值，不是整段 Cookie，也不是 SESSION。

选择“手动填写”时，可输入坐标或点击“获取当前位置”。浏览器定位需要 HTTPS 或 localhost，电脑定位可能存在偏差；服务器不会自动获取手机的实时位置。网页不需要手动填写位置描述。

保存后点击“检查登录”。该操作只验证登录并读取今日记录，不提交打卡。今日尚未打卡时显示“登录正常”；学校返回今日已打卡时提示“登录正常，今日已打卡”，账号卡片隐藏“立即打卡”。

### 4. 开启自动打卡

进入“自动打卡”，开启“每日自动打卡”，设置后点击保存。**账号勾选“参与自动打卡”和每日任务开关都开启时，才会自动执行。**

| 设置 | 含义 | 默认值 |
| --- | --- | --- |
| 大约打卡时间 | 当天首次自动打卡的基准时间 | 22:00 |
| 最晚重试时间 | 到此时间后不再自动提交 | 23:30 |
| 重试间隔 | 可重试失败后，两次尝试之间的基础间隔 | 5 分钟 |
| 最多尝试 | 每个账号当天的打卡尝试上限，包含首次尝试 | 12 次 |
| 时间浮动 | 在基准时间后增加的随机延迟，填 0 关闭 | 120 秒 |
| 位置浮动 | 在已保存位置周围允许的最大浮动，填 0 关闭 | 5 米 |

例如设置 22:00、时间浮动 120 秒，当天每个账号会得到一个 22:00:00 至 22:02:00 之间的计划时间。“总览 → 下次打卡”显示当天的实际计划。准备登录在该账号实际计划时间前半小时进行，不需要另外填写开始时间。

所有时间均为北京时间。基准打卡时间和最晚重试时间应安排在同一天，且后者晚于前者。实际提交还需满足学校接口返回的有效时段。

设置保存后，可以关闭网页、退出登录或关闭自己的电脑；任务在服务器容器中运行，服务器和容器需要保持在线。

### 5. 手动打卡与查看结果

需要立即尝试时，在账号卡片点击“立即打卡”，确认后执行。手动操作不等待随机时间延迟，但仍会检查学校时段和今日记录。

“总览”查看今日成功数量、下次打卡时间和最近操作；“打卡记录”查看每次操作的时间、账号、类型及结果，也可导出 CSV。

北京时间跨天后，账号卡片更新为“今日待打卡”，恢复“立即打卡”按钮，今日成功数量重新按当天统计。历史记录继续保留，不需要每天重新点击“检查登录”来重置显示。

## 日常管理

在项目目录执行：

| 操作 | 命令 |
| --- | --- |
| 启动 | `sudo bash mooncheck.sh start` |
| 状态 | `sudo bash mooncheck.sh status` |
| 日志 | `sudo bash mooncheck.sh logs` |
| 重启应用 | `sudo bash mooncheck.sh restart` |
| 停止 | `sudo bash mooncheck.sh stop` |
| 备份 | `sudo bash mooncheck.sh backup` |
| 更新构建 | `sudo bash mooncheck.sh update` |

查看日志时按 `Ctrl+C` 只退出日志，不停止服务。停止服务保留账号与记录。修改 `.env` 后执行 `sudo docker compose up -d`，单纯重启不会加载新的环境配置。

## 配置说明

脚本自动创建 `.env`。手动配置时复制 `.env.example` 为 `.env`，填写自己的随机长令牌，再执行 `sudo docker compose up -d --build`。

| 配置项 | 说明 |
| --- | --- |
| `DOMAIN` | 允许访问的域名或 IP，不带协议或端口 |
| `SITE_ADDRESS` | HTTPS 填裸域名，HTTP 测试填 `http://主机名` |
| `BIND_IP` | `127.0.0.1` 仅本机；`0.0.0.0` 接受外部连接 |
| `HTTP_PORT` | HTTP 端口；域名部署使用 `80` |
| `HTTPS_PORT` | HTTPS 端口；域名部署使用 `443` |
| `SECURE_COOKIE` | HTTPS 设 `1`；HTTP 测试设 `0` |
| `SETUP_TOKEN` | 首次创建总管理员的验证令牌 |

切换到域名时，修改对应项并保留原令牌：

```dotenv
DOMAIN=checkin.example.com
SITE_ADDRESS=checkin.example.com
BIND_IP=0.0.0.0
HTTP_PORT=80
HTTPS_PORT=443
SECURE_COOKIE=1
```

完成解析和端口配置后，执行 `sudo docker compose up -d`。

## 备份与迁移

运行后生成的 `data/` 保存账号、计划和记录。`master.key` 是解密学校凭据的密钥，必须与数据库一起保留。

```bash
sudo bash mooncheck.sh backup
```

备份会短暂停止应用，完成后恢复此前运行的应用。备份文件在 `backups/`，包含完整 `data/` 和 `.env`，请下载到其他位置妥善保存。

迁移步骤：

1. 执行 `sudo bash mooncheck.sh stop` 停止旧服务。
2. 将程序文件、完整 `data/` 与 `.env` 复制到新服务器项目目录。
3. 修改 IP 或域名解析，在新服务器执行启动命令。
4. 登录并检查学校接口连通性，确认后开启自动任务。

不要让新旧服务器同时为同一账号运行自动任务。恢复备份时也应先停止服务，再放回数据和配置。

更新前先备份。Git 部署执行 `git pull --ff-only` 后运行更新命令；ZIP 部署只替换程序文件，保留 `.env`、`data/` 和 `backups/`。不要执行 `docker compose down -v`，它会删除 HTTPS 证书卷。

## 常见问题

**启动成功，但公网打不开？**

运行 `sudo docker compose ps`。若端口显示 `127.0.0.1:8080`，处于本机测试模式，开放防火墙也无法直接访问。请使用 SSH 转发或按上文配置公网访问。

**`init` 显示 Exited 正常吗？**

正常退出码 `0` 表示数据目录初始化完成。长期运行的是 `app` 和 `gateway`；`app` 应显示 healthy。

**HTTPS 申请失败？**

检查域名 A/AAAA 记录、80/443 外网连通性、端口占用，以及 `sudo bash mooncheck.sh logs` 的输出。

**如何重置总管理员密码？**

```bash
sudo docker compose stop app
sudo docker compose run --rm --no-deps app python manage.py
sudo docker compose start app
```

**学校登录或打卡失败？**

核实账号、信任浏览器、位置和学校允许的时段；服务器必须能访问学校平台。系统按学校接口返回的今日记录确认结果。
